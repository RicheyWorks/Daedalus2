The pilot is a C++ runtime port of the standard single-player board loop in
[Minesweeper Pro](https://github.com/RicheyWorks/minesweeper-pro/tree/63156079e141bca2b0cd3a0f297bb6595b28c2d0),
which is a Java game. It is not a Python game port. The pinned `GameService.java`
blob is `30e6e58ff5d0d3795bb64a209c82342ed227f605`.

`minesweeper_source_oracle.py` reads that exact blob from an existing original
checkout, checks its Git object SHA, extracts eleven actual Java rule methods,
and executes them with JDK `javac`/`java`. It never starts JavaFX, Spring, Redis,
PostgreSQL, the original application, or a server. Board/Cell storage and
infrastructure collaborators are small stubs. The AI collaborator affects only
an unreachable `winProbability > 0.9` flavor branch in this source; outcome
logic is unchanged. Two `System.currentTimeMillis()` calls are replaced by a
controlled clock; `startTime` is set to epoch zero, preserving source score
arithmetic while removing scheduler/timezone noise.

```powershell
python engines/unreal/core-test/minesweeper_source_oracle.py --source-repo C:/Users/730ri/projects/minesweeper-pro
```

The committed `minesweeper_parity.txt` is generated by that executed source, not
by C++ or a handwritten implementation of Minesweeper. `minesweeper_core_test.cpp`
loads each fixed mine layout, replays every action, and compares each complete
cell snapshot, outcome, score, revealed count, flag count, and mutation/no-op
result. It also checks generation properties and input bounds independently.

Source rules retained: eight-neighbor zero-region flood reveal, flags block
reveal/flood, revealed cells ignore flag/reveal, single mine hit loses, all safe
cells revealed wins, or all mines correctly flagged with no wrong flags wins.
Terminal boards ignore subsequent actions. Win score is
`max(150 * mine_count - floor(max(elapsed_ms, 0) / 500), 0)` for this standard mode.
Scores freeze on completion. The source game creates and times the board before
any reveal: its configured safe cell is not necessarily the first cell clicked.
Normal desktop startup chooses the center; restart chooses `(0,0)`.

Generation retains the source configured-safe 3x3 exclusion, falling back to
protecting only that cell when the requested mine count cannot fit outside the
zone. The new seeded runtime RNG is reproducible but does not reproduce Java
SecureRandom boards; fixed layouts are the cross-language parity boundary.

Explicit pilot limits: 1..32 rows/columns, 1..cells-1 mines, standard single-player
mode only. It omits adaptive server population/streak mine counts, scheduled
board resizing, challenge lives, shields, reveal blasts, pencil probabilities,
AI hints, economy, accounts, multiplayer, leaderboards, and persistence. Java
throws on invalid coordinates; C++ returns false with identical preserved state.
Invalid configurations are rejected atomically. C++ caps extreme elapsed time
before arithmetic can overflow; the source casts its time penalty to `int` and
can wrap for durations outside a normal game. This safeguard is tested separately
and is not claimed as exact parity with that overflow behavior.

The source replay `GameEvent` has coordinates/messages/timestamps but no initial
mine layout; `ReplayVisualizer` marks events over the current view rather than
rebuilding board state. The portable test transcript includes the initial layout
to make replay deterministic.

These tests establish native rule parity for the scoped loop. They do not prove
Unreal compilation, Blueprint/Slate binding acceptance, or live in-game play.

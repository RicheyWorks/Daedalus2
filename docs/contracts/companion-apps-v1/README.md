# Companion app capability coverage

[capability-map.json](capability-map.json) records the four inspected apps, their original feature groups, existing interfaces, source pins, native bindings and remaining implementation. Paths in an app entry are relative to that app's repository. Native paths are relative to Daedalus2. The map is an inventory and implementation contract, not an executable install manifest or proof that every feature is connected.

The inspected Daedalus baseline is `5887f860be17f6d7356f9393599c005dc83450b3`. Its photo, image and study actors launch the existing apps' private browser interfaces. Their pairing/opened states do not establish completed work. The additive `ADaedalusPhotoPdfTerminal` / `FDaedalusPhotoPdfClient` source is written: selected PNG/JPEG bytes, authenticated session/job requests, real job status, download, cancellation and explicit local export. These are source implementations pending exercise, not runtime results. Conversion delegates to PhotosToPDFPC's existing PDFBox service. It adds no folder scan, multi-page merge, OCR or physical printing. This new source is **unverified and not installed**; tests and builds are deferred at the user's request.

Image Optimizer and Synapse already expose useful same-process services, but native job/card interfaces remain unbound. Fax exposes the existing authenticated server API; it has no local realm bridge or native actor. Fax confirmation is not called by this integration. Real transmission, new credentials, paid services and external deployment are outside the authorized work.

Static source review of the new file helpers and Slate panel is complete. The identified ancestor-path and temporary-file identity findings were addressed in source using retained local directory handles and handle-based no-replace commit/cleanup. This is code-review evidence only; Windows dialog/file API behavior, native build, installation and real interaction still require the operator's verification.

Protocol differences are intentional. Photo and image use `/v1/sessions` and `X-Session-Token`; Synapse uses `/v1/session`, `X-Desk-Session`, a single claimed session, and requires the exact local `Origin` on mutations. Photo has a protocol identifier without a product identifier. Photo cancellation releases its action key; image cancellation retains a tombstone. Native implementations must preserve these differences and retain stable action identity after uncertain responses.

Desktop-only groups remain visible in the map instead of being counted as integrated or silently removed. Existing app/module, connector, plugin and example inventories are scoped to inspected tracked sources; general Daedalus plugin infrastructure is not an implementation of an app connector. No installed application, current user's documents/vault, provider service, Unreal editor or runtime was operated for this inventory. Only `codex-play-guard` may perform the eventual native install, binding and Play verification. Acceptance must record the exact installed source, physical object binding and observed real app result separately from delivery of a handoff.

Photo terminal input lifecycle correction (claim31157): UI-only viewport input replaces controller move/look ignore counters, which Unreal controller restart can reset before the old panel closes. Owned viewport restoration now also survives opening-controller destruction. This is a separately reviewed source correction with refreshed install-manifest hashes; builds, tests and native behavior remain deferred. Synapse's stack must inherit this corrected photo revision rather than duplicate its commits.

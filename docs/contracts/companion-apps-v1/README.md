Protocol differences are intentional. Photo and image use `/v1/sessions` and `X-Session-Token`; Synapse uses `/v1/session`, `X-Desk-Session`, a single claimed session, and requires the exact local `Origin` on mutations. Photo has a protocol identifier without a product identifier. Photo cancellation releases its action key; image cancellation retains a tombstone. Native implementations must preserve these differences and retain stable action identity after uncertain responses.

The image workbench must freeze both selected bytes and settings after an uncertain submission, recover that exact action before replacement or cancellation, and respect readable canceled tombstones. Its IOP1 frame has a 15-byte header; the complete envelope is bounded to 24 MiB, and all generated outputs together to 32 MiB. Actual encoded dimensions and byte counts are results from the existing encoder. JPEG loses transparency, and output size can increase; no compression saving is promised. Export must create a new, explicitly chosen local image file without overwriting existing data.

The Synapse client must check capabilities before consuming its single claim. A lost session response needs a fresh link from the desktop; a lost score response instead retains the exact card/revision/score/action UUID for explicit retry. Disconnecting or closing cannot undo a review already saved. Prompt, context and revealed answers are local plain text, never executable markup or paths; the permission grants selected IDs, not a whole vault or an immutable snapshot of card content. No new request may broaden this permission.

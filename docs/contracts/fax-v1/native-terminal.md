# Native prepared-fax terminal

`ADaedalusFaxPreparationTerminal` is another local interface to Fax Trident's existing approved preparation job. It contains no fax sender, upload/prepare workflow, backend login or provider integration. The existing desktop prepares the selected PDF/recipient and approves one immutable job through the companion bridge; native interaction reads that exact grant.

This source stack starts at Daedalus contract `ceef882fef943acd60b3c6cb8d16f5dae18c993a` (PR159), which pins the real app bridge `9e37b26aaaa812108c43a407cef4dc4e43975a2c` (fax PR4). Photo correction5e14, Synapsec3f8 and Image4f82 remain inherited. Exact source and dependency hashes belong to [native-install-binding-manifest.json](native-install-binding-manifest.json).

## Interaction and authority

After an authorized native installation, interact with `/Script/DaedalusLink.DaedalusFaxPreparationTerminal` as the nearby possessed local Hero. Its mesh is an engine cube placeholder; art/placement/Play are separate. Use the existing desktop's Realm preparation action, signed into literal `http://127.0.0.1:<port>`, and explicitly approve the PDF/recipient before copying its private local link. Paste that typed link into the terminal's masked field.

The native client validates `faxprep.local.v1`, `productId:fax-trident`, `fax.prepared.read`, `fax.prepared.cancel`, `selected_prepared_pdf` and exact limits before reading the job. This protocol has one expiring local grant and no session-claim endpoint. It must not use the photo/image session routes, the Synapse session header or the old typed browser enum. The new terminal has its own strict literal-loopback grammar; the old enum remains unchanged.

The panel displays actual job ID, recipient, SHA-256, pages, bytes, document expiry, grant expiry and state. Refresh reads the same approved job. PREPARED is not sent. Existing desktop actions may operate separately; native display is not independent transport/delivery evidence. Only current service state is authoritative.

Download explicitly retrieves the exact approved PDF. The native client checks MIME, bounded bytes, exact digest, PDF envelope and unchanged job tuple, then rechecks state before export. Actual structural/page validation remains with the existing companion's PDFBox service. The explicit Windows chooser suggests `prepared-fax-review.pdf` and creates only a new chosen file. The shared photo exporter preserves retained ancestor handles, owned temporary identity, failure cleanup and no-replace commit. An observed canceled/expired job cannot start a new export; copies already emitted/downloaded/saved cannot be recalled.

Cancel requires an explicit second action bound to the displayed immutable job. It requests only the existing pre-submission cancellation route. An uncertain result keeps that same job and requires explicit refresh/reconciliation. It cannot recall a submission or create another fax. Local revoke/close removes the local capability only; it does not cancel the upstream job, delete its source upload or log out the desktop. The source upload's one-hour and job snapshot's 24-hour leases remain separate.

## Local boundaries and lifecycle

Only the fixed `/v1/capabilities`, `/v1/job`, `/v1/document`, `/v1/cancel` and `/v1/grant` routes are used. Bearer capability, exact local Origin on mutations and literal Host stay transient. No redirect, proxy, netrc, returned arbitrary URL, server file path, backend JWT, automatic retry/new job, replication, config, save, analytics or logging stores this data. The paired link is cleared from the input/undo buffer after use and on close.

The client is game-thread driven with a bounded serial HTTP worker and guarded completions. The actor binds its opening local controller/Hero/world/realm/viewport and mapped Slate user, follows the corrected UIOnly ownership design without controller ignore counters, and restores only owned state. Weak actor and panel-generation checks surround asynchronous downloads and modal file export. Cancel, revoke and close invalidate delayed exports. Closing requests bounded best-effort local grant revocation; an unconfirmed revoke remains unconfirmed and grant expiry is authoritative.

Source/API limits are 25 MiB PDF, 1–100 pages, one immutable approved job and at most 900-second local permission. Native transport and JSON bounds are recorded in the install manifest. The companion's PDFBox page geometry limit is14,400points. These are configured/source limits, not measured timings or total CPU/heap guarantees.

## Completion and verification

The native source implementation and shared export-helper reuse are distinct from its installed behavior. Safe focused offline app validation is now authorized by the latest user instruction; exact commands/source revisions/results are separate evidence, and historical source-only manifests must not be read as new passing tests. No real fax, new credential, external paid action or editor takeover is authorized by this work.

Only the existing `codex-play-guard` owns Unreal compilation/loading, binding, physical placement and Play coordination. Native compile/UHT/link, actual dialog/focus/controller behavior and end-to-end synthetic app use require separate receipts. A source review or PR is not installation or Play acceptance. The four-app capability map keeps the remaining desktop and transport gaps visible.

Native envelope compatibility is deliberately strict: percent-PDF must start at byte zero and a terminal EOF marker must precede only trailing whitespace. Some PDFs accepted leniently by PDFBox are rejected rather than rewritten. No native full decode/sanitization claim is made.

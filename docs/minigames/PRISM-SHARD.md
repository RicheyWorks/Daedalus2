# Shardring Resonance (prism sphere shard minigame)

Module: `tools/minigames/prism_shard.py` (pure Python, stdlib, seeded). Tests: `tools/minigames/test_prism_shard.py`.

## Play
A cracked prism sphere has a ring of empty facets. Each turn one Prism Shard of a hue arrives (the next one is shown). Set it in any empty facet. Three or more facets of one hue in a row (the ring wraps) resonate and clear for run^2 x chain points; consecutive resonances raise the chain. Every third resonance of a hue summons that Warden's spirit: +25 and the spirit clears one more facet.

Game over: every facet is full (the sphere shatters, lost) or the shard pouch is empty (won).

| difficulty | facets | hues | shards |
|---|---|---|---|
| easy | 14 | 3 | 60 |
| normal (default) | 10 | 3 | 50 |
| hard | 8 | 3 | 40 |

API: `g = prism_shard.start(seed, "normal")`, `g.place(facet)`, `g.status()` (score, over, won, ring, spirits).

## Play mode, demo, save
- `python -m tools.minigames.prism_shard --play --difficulty normal --seed N`: text ring, type a facet number (q quits).
- `python -m tools.minigames.prism_shard --demo --seed N`: plays a full seeded game with the greedy helper; same seed, same output.
- `g.to_state()` returns a JSON-safe dict (v1, includes the RNG state); `ShardringGame.from_state(d)` resumes the game exactly. A host save slot can store it later.

## Browser version
Open `tools/minigames/web/shardring/index.html` in any browser (one file, no server, no downloads). Pick a seed and difficulty; click a facet, or use Left/Right + Enter/Space, keys 1-9/0 for facets 1-10, R to restart.
The page's `shardring-core` script ports the Python rules and CPython's `random.Random(str)` (SHA-512 seeding + MT19937 + `choice`), so the same seed and difficulty give the same shard sequence and game as `prism_shard.py`. `test_prism_shard_web.py` builds fixtures from Python (shard sequences, full greedy games, final state for 18 seed/difficulty cases) and checks them with `node tools/minigames/shard_web_test.js` (skipped if node is missing).

## Controller
The page reuses the shared DaedalusPad layer (`daedalus-server/src/main/resources/static/controllers/daedalus-pad.js`, the same module the Prismheart demo uses; see `docs/controllers.md`). It loads it by a repo-relative path and feature-detects `window.DaedalusPad`, so the page still works with mouse and keyboard when the module is absent; nothing is fetched from the network. Shardring only maps DaedalusPad's logical actions (`Shardring.PAD_ACTIONS`): D-pad / left stick (up/left = previous facet, down/right = next), confirm (A, or the family's confirm button) = set shard, menu (Start) = restart. Keyboard and pad share `Shardring.applyVerb`. `shard_pad_test.js` drives the real module with a fake standard gamepad. The pad module itself is unchanged.

## Native port parity (C++ / Unreal)
`data/minigames/shardring-parity-v1.json` (schema `daedalus.minigames.shardring_parity/v1`) is generated from `prism_shard.py` by `python tools/minigames/shard_parity.py`; `--check` (and `test_shard_parity.py` in CI) fails if it is stale. It never changes the rules: after a rules or balance change, rerun the generator and commit both.

- `rules`: hues, spirit names, difficulty table, run length, spirit cadence and bonus, and the RNG contract (CPython `random.Random(str)`: SHA-512 seeding, MT19937, `choice` via `getrandbits`; the web page's port is a reference).
- `cases`: 3 difficulties x seeds 0, 1, 42, 2024. Each has `rng_seed_string` (`shardring:<seed>:<difficulty>`), the first 64 raw `sequence` draws, every move (`facet`, `shard`, `gained`, `score`, `chain`, `spirit`, `ring_before`, `ring_after`, `next_current`, `next_next`, `pouch`), `to_state()` `snapshots` after moves 5 and 20, `final` status and `result`.

How a native port should use it:
1. Seed check: rebuild the RNG from `rng_seed_string` and match `sequence`.
2. Replay: start the case, assert `ring_before` and `shard`, call place(`facet`), assert every other move field; then assert `final` and `result`. Moves follow `policy` (greedy), but replaying the listed facets is enough.
3. Save/load: load each snapshot `state` (RNG state is CPython's `getstate()`: version, 625 words, gauss), replay the remaining moves, and match `final`.
A port can skip the SHA-512 seeding by loading the RNG from a snapshot, but full parity needs step 1.

## Realm cabinet
`shardring` is now a registered desktop cabinet (`DesktopGames/DaedalusDesktopShardringCore.h`, `ShardringGame`, registry id `shardring`), so `realm_cabinets.py` places it like any desktop game with host `ADaedalusDesktopArcade`, a crc32 seed and `StartGame("shardring", seed)`; the Prismheart row and the two glob realms that pick it up are in `data/minigames/realm-cabinets.json`. The Python module stays the rules authority: `minigame_catalog.py` drops a Python game from `python_games` once it has a native factory. Cabinet controls: Left/Up previous facet, Right/Down next, J/Space/pad A sets the shard, R or pad Start restarts a finished ring. Cabinet difficulty is the game difficulty; option 0 Resonance, option 1 Guide practice (marks the greedy facet). Save slot `shardring.dgs` (Manual; the save records how many 32-bit words were drawn and fast-forwards on restore). The cabinet draws from `DaedalusPyRandomCore.h`, a C++ port of CPython's `random.Random(str)` (SHA-512 seeding, MT19937 `init_by_array`, `_randbelow_with_getrandbits`), seeded `shardring:<seed>:<difficulty>` exactly like `prism_shard.py` and the web page, so `StartGame("shardring", seed)` is the same game as `prism_shard.start(seed, difficulty)`. `desktop_games/shardring_test.cpp` replays all 30 fixture games twice: with the recorded draws injected via `UseOracle`, and from seed + difficulty alone.

## Native core (Unreal side, source only)
`engines/unreal/DaedalusLink/Source/DaedalusLink/Public/DaedalusShardringCore.h` is a plain C++17 port of `ShardringGame` (`Start`, `SetShard`, `GreedyMove`, `RunAt`, spirit summons, the difficulty table). It does not port CPython's PRNG: every `random.choice` the rules make reaches the core through an `Oracle` (next hue, spirit facet) that the host supplies, so a native host either asks the Python rules for the draws or replays a recorded sequence. Parity: `tools/minigames/shardring_parity.py` plays 10 seeds x 3 difficulties with `greedy_move` and writes `engines/unreal/core-test/shardring_parity.txt` (every draw and spirit pick, every move, the end line); `engines/unreal/core-test/shardring_core_test.cpp` feeds the draws to the core and must reproduce every line (engines.yml, gcc+ASan and clang). `desktop-games.yml` fails if the fixture is stale (`shardring_parity.py --check`). The native host / `ADaedalusDesktopArcade` binding is the next step; in-editor placement is the editor custodian's.

## Cabinet conventions (all seven Prismheart cabinets)
Every `DesktopGames/DaedalusDesktop<Game>Core.h` follows one shape so a reviewer can read any of them cold: core state + `SessionSeed` + `Option` + cursor/latches; `Deal()` restarts from the seed and `ResetTable()` clears cabinet-only state; input goes through `SourceKey` / `PadButton` names and `EdgeLatch` (never raw `Key==5` or hand-kept `Was*` flags); saves are written with `SaveWriter` and read with `SaveFields` from `DesktopGames/DaedalusDesktopSaveText.h` (exception-free, every number range-checked, lists as comma text with `-` for empty), with the PRNG re-seeded and fast-forwarded or the state regenerated from the seed and replayed rather than trusted; `Render` names its palette once and draws in labelled passes. `desktop_games/save_text_test.cpp` covers the shared helper. Keep that shape when adding a cabinet; see "Craft" in `AGENTS.md`.

## PyRandom parity (the PRNG on its own)
`DaedalusPyRandomCore.h` is a bit-exact port of CPython's `random.Random(str)` (SHA-512 string seeding, MT19937 `init_by_array`, `getrandbits(32)`, `_randbelow`, `randrange`, `random()`, both `sample` branches, `shuffle`). `tools/minigames/pyrandom_parity.py` records every method on eight seed strings (game-style, empty, 64-char, UTF-8) as one continuous stream per seed plus the words-consumed count; integer seeding too (`SeedInt(int64)` and `SeedBigEndian(bytes)` for the SHA-256 digest path, per `docs/islands/DISKSAVER-SEED-SPEC.md` section 1: abs(n) in 32-bit limbs, least significant first, high zero limbs dropped), so the Disk Saver layout tools can share the generator; `engines/unreal/core-test/pyrandom_core_test.cpp` replays it call by call and proves `Drawn()`/`Discard()` fast-forward continues the stream identically (engines.yml gcc ASan + clang; desktop-games.yml fails if the fixture is stale). Game fixtures prove the games; this proves the generator, so a drift is named at the first call rather than the first differing seam.

## Prismchime Ring (new original game, unreal-team)
`tools/minigames/prismchime.py` (rules authority, on `prism_common.PrismGame`): a ring of 6/8/10 chimes with seeded charge (1-2) and facing; tapping a chime pulses its charge along its facing (+1 per hop) and the rung chime gains one; a chime reaching 4 peals (+5), lights, resets and charges both neighbours, resolving in fill order, so peals chain; light every chime within 8 taps to win (+3 per tap left). Only `randrange` is drawn. `DaedalusPrismchimeCore.h` is the header-only port on PyRandom; `tools/minigames/prismchime_parity.py` writes `engines/unreal/core-test/prismchime_parity.txt` (30 rings, demo taps) and `prismchime_core_test.cpp` regenerates it from seed (engines.yml gcc ASan + clang; desktop-games.yml fails on a stale fixture). Placement: Prismheart realm row (`realm-arcades.json` include list; the Daedalus spot comes with the cabinet); the cabinet is `DesktopGames/DaedalusDesktopPrismchimeCore.h` (registry id `prismchime`, save slot `prismchime.dgs`; Left/Right walk the ring, A taps, option 1 Guide rings the watcher's chime; no draws after start, so saves range-check the ring instead of fast-forwarding), replayed by `desktop_games/prismchime_test.cpp`; spot "the chime ring".

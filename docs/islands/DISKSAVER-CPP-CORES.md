# DiskSaver: C++17 ports of the minigame cores (G573 batch 1, G574 batch 2)

These are header-only, engine-free C++17 ports of the pure logic of the DiskSaver Python minigames, so a game
build can grade a player's moves without Python. None of them includes Unreal headers or uses UObject,
and none needs exceptions or RTTI: they build with `-fno-exceptions -fno-rtti` and MSVC `/GR-`. Errors come back
as `Error` codes. Any Unreal glue will be a thin separate wrapper later.

**Layouts stay in Python.** The seeded layouts use Python's `random`, which the ports do not reimplement. Each core takes the
puzzle as the Python tool laid it out (card pair ids, chart edges, the yard's `draw()` rows, sacks per bin, quay walls/marks/dock/start, barge lanes, channel path/sites/hulls, lot values/coin). Overflow
is guarded by size caps: 64 cards, 12 chart nodes, a 7x7 yard with a 4M-state BFS cap, 8 bins / 24 sacks, 4 seal marks, 8 barge lanes with |velocity| <= 9, 6 skiffs / 12 sites / hull 1000, 8 lots with value and coin caps, rope grips <= 9 with a 200M-visit DFS cap, 7 bells and 8 wagons with 4M-state BFS caps, 40 watchfire islands (uint64 bits, 50M-node search cap), 60 lock boats (1M memo entries, plans up to 4096 groups), 40 smuggler suspects (4M memo sets) 64 KiB of cryptogram text (ASCII), 8x8 sounding grids (uint64 cells, 50M-call solver cap), 400 quay crates of at most 10^12 KiB, 4096 last-crate weights of at most 10^9 KiB, and 20 riddles with 64 KiB answers.

**Golden files.** `tools/streaming/disksaver_cpp_parity.py` runs each tool's real `play()` path and writes
`engines/unreal/core-test/disksaver_<game>_parity.txt`. The cases are the real `tools/world_census` fixtures under several seeds,
synthetic censuses, and hand-laid edges (an unsolvable corner yard, a disconnected chart, wrap-around chutes, a walled-off dock, a solid barge lane, a chart with no post sites, a sale with no coin), plus
refusals. Each `disksaver_<game>_core_test.cpp` (no framework; shared helpers in `disksaver_parity.h`) asserts every line:
layout, par, plan, and each play's result or refusal. Single-line mutations of the golden files make the tests fail.

    python tools/streaming/disksaver_cpp_parity.py --check
    cd engines/unreal/core-test
    g++ -std=c++17 -O1 -Wall -Wextra -Wshadow -Werror -fno-exceptions -fno-rtti -fsanitize=address,undefined \
      -I../DaedalusLink/Source/DaedalusLink/Public disksaver_sack_chute_core_test.cpp -o t && ./t disksaver_sack_chute_parity.txt

CI: three steps in the `engines.yml` mesh-parity job: gcc with ASan/UBSan, clang, and a check that the golden files match the Python tools. The steps loop over every `disksaver_*_core_test.cpp`, so a new batch needs no workflow edit.
**Text is ASCII.** Harbour Cryptogram, Census Riddles and Fleet Soundings handle text as bytes: Python's Unicode `upper()`/`lower()`/`strip()`/`int()` and its code-point row lengths agree with the ports on ASCII input only (for example `ß`, dotless `ı` or Arabic-Indic digits can grade differently). The golden files are ASCII.

**The Python-game port list is complete** (G546, G549-G566 except G547/G548, which are not mine; batches G573-G577). The cores were also replayed against mutated golden lines (dropped, duplicated, truncated and out-of-range tokens) without a crash.

**Batch 6 (G578): the earlier simulations G166, G171, G175 and G179.** These tools draw from Python's `random.Random`. The ports do not reimplement it: the golden writer records every draw a run makes (its tape) and the C++ core replays the same simulation on that tape. Each draw is checked against the range the caller asked for, and the tape must be used up exactly; otherwise the run reports a tape error. Left in Python: the JSON config schema, NPC lines, reading the G86 shoals and G39 Byte Spring files (the golden file carries the islands and the budget cap), and the CLI. Tidemark Chunks dedupes chunks by their bytes; Python keys them by SHA-256, which gives the same counts here (the test checks the vault cost against a plain byte-for-byte oracle). Caps: 64 islands and 10,000 steps (Tide Clocks), 2M writes (Lighthouse Leases), 64 MiB of version bytes (Tidemark Chunks), 4M bottle posts (Bottle Census); size products are checked before multiplying. Tidemark hashes bytes, so it is not affected by text encoding. The golden files are ASCII.

Authorship: the board lists disk-saver as owner of all four, but bottle_census.py was first committed under another bot's name (`e724f01f8`, #532). This port only adds files; it does not change bottle_census.py or anything else of theirs.

**Batch 7 (G579): the G206 census budget tools G253, G505, G529 and G533.** They price a census with the G206 model, so they reuse the G571 port `DaedalusCensusBudgetCore.h` through a small shared header, `DaedalusDiskSaverCensusPlanCore.h`, which ports `census_budget.plan()`'s checks and ordering (budget ranges, empty census, blank or duplicate world ids, duplicate slots, worlds sorted by id). These tools draw nothing at random. The golden file carries each case's inputs (census or report lines, budget, config, sweep text) and the tool's output lines, and the seeded variants of the real census are made in Python and written out. Left in Python: JSON loading and schema checks (format, version, types, row shapes), reading the config files and an existing G206 report, Beacon Watch's `budget_changed`/`cost_model_changed` (JSON compares), Fleet Flags claims that are not integers, text output and the CLIs. The tests add their own checks: Ebb Tide's DP against a brute force on worlds of up to 16 islands, Budget Fathoms' green budget against the G206 beacon one KiB lower, a Beacon Watch report against itself (calm), and every Fleet Flags world in exactly one realm. Caps: 100,000 worlds, 10^6 islands and 10^12 asset definitions per census (so every sum and x1000 product fits in 64 bits), a 8M-word knapsack table, 64 sweep values, 4 KiB ids. **Text is ASCII here too:** world and realm ids are compared as bytes (UTF-8 byte order is Python's code-point order), but blank ids and sweep values are judged on ASCII whitespace and digits only, where Python's `strip()`/`isdigit()` also accept non-ASCII ones. The golden files are ASCII.

**Batch 8 (G580): G531 Stray Cargo, G519 Memory Footprint, G517 Budget Trend Ledger, G544 Caulking Check.** Memory Footprint and the ledger read G206 reports, so census cases go through `DaedalusDiskSaverCensusPlanCore.h` and the G571 `DaedalusCensusBudgetCore.h`; raw report cases are also written out. Nothing here is random. Stray Cargo sorts findings by their `json.dumps(sort_keys=True)` text, and Caulking Check reports findings as JSON, so a small `DaedalusDiskSaverPyJsonCore.h` writes Python's exact `json.dumps` text (ensure_ascii, `\uXXXX` escapes and surrogate pairs, sorted keys, both separator styles). **The duplicate-JSON-key check is ported**: the scanner follows CPython 3.10's C scanner (code-point positions, the same error messages up to the colon, BOM refusal, `Extra data`, duplicate keys reported when an object closes, 512 levels then a capacity refusal) and matches Python on every golden case. Golden files written by Python 3.10 (CI) and 3.13 are byte-identical; cases whose messages differ between versions (trailing commas, 4300-digit integers) are left out. The tests add their own checks: Stray Cargo counts add up to its findings, a ledger record diffed with itself is steady, a win only clears an over-budget world, and every Caulking finding's own JSON passes the scanner. Caps: 100,000 worlds and 10^6 islands/assets, 10^13 per Memory Footprint field and 4x10^15 totals (x1000 fits in 64 bits), 10^15 KiB per ledger world, 100,000 ledger runs, 64 KiB names, 4 MiB per checked file, 64 MiB and 100,000 files per survey. Mutation run: 43 of 46 single-line edits caught; the 3 missed are equivalent (an island's asset count 3 to 33 and 5 to 55 where no finding reads it, and `--wins 10` to `100` with fewer than 10 candidates).

**The DiskSaver lane port list is complete** (batches G573-G580). What stays in Python on purpose: every tool's JSON loading, schema/version checks and CLI; seeded layouts and `random` (the ports replay recorded tapes or written-out layouts, never reimplement it); reading config, census, shoals and report files; Memory Footprint's `tool_footprint` folder reading; the ledger's file reading, appending and run picking; Caulking Check's folder walk, backslash paths and non-ASCII extension lowering; Stray Cargo values that are floats or lists; Beacon Watch's budget/cost-model JSON compares; Fleet Flags' non-integer claims; and all text output.

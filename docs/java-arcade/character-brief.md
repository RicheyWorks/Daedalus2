# Blender brief: Java arcade cabinets

This brief accompanies the Sudoku/Blackjack local cabinet interfaces; it does
not assign new ownership or claim models are built/imported. Coordinate with
the established Blender and Unreal owners before production export or import.

## First useful character and cabinet scope

- Create an original Daedalus arcade cabinet shell with distinct Sudoku and
  Blackjack display/signage variants, clear standing space and an interaction
  anchor. Keep the current Slate display for pilot acceptance; a world-space
  screen can follow after runtime acceptance.
- Sudoku needs a readable board frame and optional original host later. Digits,
  fixed clues, editable selections and hints must remain legible; character art
  must not obscure the board or imply access to its solution.
- Blackjack gets one original stylized dealer, a table surface and generic card
  backs/chips. Existing source personas are procedural desktop palette/cast data,
  not verified Blender meshes or rigs. Start with one cleared identity.
- Dealer animation cues are presentation only: idle, greet, receive bet, deal,
  hit, reveal after Java allows it, win/loss response and leave. Derive cues from
  visible DTO changes; animation must never deal cards, decide outcomes or reveal
  a live hole card/future shoe.

## Reviewable production requirements

Follow the team's existing rig, scale, orientation, material/export and LOD
standards rather than introducing a new pipeline. Include the Blender source,
export manifest and exact asset IDs/hashes; record polygons, textures, skeleton,
origin and animation list. The Unreal owner accepts exact imports, collision,
interaction anchors, screen readability and animation timing in world.

Cabinet identity, Java account/session identity and any future NFT/entitlement
identity stay separate. The user's desired broad commercial reuse after purchase
applies only to user-owned or separately cleared code/assets. Use original or
cleared production branding; do not transfer third-party IP, change licenses,
mint/sell tokens or assume procedural personas clear an external likeness.

No 3D assets, rigging, editor lease, imports, deployment or licensing changes
were performed in this integration. Shared audio remains with its current owner.

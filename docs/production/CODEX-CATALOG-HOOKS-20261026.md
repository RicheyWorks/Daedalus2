# Catalog READ integration hooks — 26 October 2026

Source baseline: `800a7e7f746fca1f050d38295e4a50289b5ba487`. This is a source inventory, not runtime acceptance. No application endpoint or native runtime was invoked. `AlgorithmCatalogController.java` is absent at this baseline; the real algorithm read is in `MazeController`.

| Real HTTP read | Payload / version | Authoritative implementation | Existing consumer / bounded gap | Smallest useful follow-up and prerequisites |
|---|---|---|---|---|
| `GET /api/v1/inventory/{realm}/catalog` | JSON `InventoryCatalog{realm,theme,tabs,slots,items}`; item fields `id,tab,slot,actions,name,detail`. API path v1; **no JSON version field**. Server resource grammar is **`DIC 1`**, not the HTTP response encoding. | [Controller][inventory-controller] → [service][inventory-service] → [contract][inventory-record]. | Unreal already loads bundled `.dic` files in [Hero][hero-inventory] and parses them with [InventoryCore][inventory-core]. Held/Worn state is supplied separately. No HTTP JSON catalog consumer was identified in the bounded search. | Only if remote refresh is required: existing Hero/UI owner agrees JSON-to-Catalog mapping, realm naming and bundled fallback/parity. Reuse that consumer; do not feed JSON into the DIC parser or create another catalog service. |
| `GET /api/v1/algorithms` | JSON `{generators:[],solvers:[]}`. Each [descriptor][algorithm-record] has `id,displayName,category,complexity,biasNote,description`. API path v1; no payload version field. | [MazeController catalog method][algorithm-controller] → [AlgorithmCatalogService][algorithm-service]. | Browser [selector][algorithm-client] calls `/algorithms` through the existing [v1 API helper][browser-api]. An existing client hook is present. | Reuse the browser hook; no additional endpoint/stub is justified by this trace. A native selector would first need an explicit consumer requirement and owner claim. |
| `GET /api/v1/world/{id}/package` | ZIP: `manifest.json`, `world.glb`, `README.txt`, optional `assets/ark.glb`; embedded package format/version **`daedalus-world-package` / 1**. Optional `mesh=faces` (default) or `greedy`. | [WorldPackageController][package-controller] → [WorldPackageService ZIP builder][package-service]. | [Python importer][package-reader] already downloads this route (default `greedy`) and validates package v1 plus glTF 2.0. [Bridge command][package-bridge] wires `daedalus.import_world` to this pipeline in source. | Existing hook, not a missing importer. Its [legacy import path][package-import] replaces assets, removes prior own-folder actors and saves a fixed level. Existing Unreal owner must provide preservation-safe destinations/replay before production reuse; later native acceptance requires the sole operator's approved window. |
| `GET /api/v1/world/{id}/package/manifest` | [WorldManifest JSON][world-manifest]: `format`, `version=1`, world/geometry, palette/layout and asset/live references. Same optional mesh modes. | [Controller][manifest-controller] → [service format/version][package-version] → [record][world-manifest]. | [WorldActor][native-fetch] fetches the manifest; [ReadManifest][native-manifest] consumes title/style, mount, palette, islands and gates, then polls live chunks/arks. This is an existing native hook, not a GLB downloader. | `ReadManifest` has no format/version refusal. Small next fix belongs to the existing Unreal owner: reject unsupported envelopes before applying data, with valid/unsupported fixtures; runtime acceptance stays separate. |
| `GET /api/v1/world/{id}/package/world.glb` | Binary glTF 2.0; same mesh modes. ETag contains world/revision and the greedy-mode suffix. | [Controller][glb-controller] → [WorldPackageService][package-version]. | No standalone-route fetch was identified in the bounded search. The existing ZIP reader already consumes `world.glb`; WorldActor uses live chunk reads instead. | No extra stub is justified merely by an unused route. If standalone geometry is required, extend the existing manifest/GLB pipeline after agreeing the consumer owner and revision/mode pairing. |

Exact inventory lookup keys are `world-zero`, `gallery-city`, `parcels`, `bricks`, `labyrinth`; lookup does not normalize the path value. These reads expose definitions/exports, not a player's bag. Catalog `actions` declare action identifiers; they do not authorize equip, craft or quantity changes. [InventoryCore][inventory-core] emits intents for its host to execute.

Searches used discovered contract names/routes in desktop source, web static clients, Unreal plugin source/Python and `tools/unreal`. “Not identified” is bounded evidence, not a whole-project absence claim; helper-only importer references were not counted as download consumers. Component maintainers are not established by the inspected files. Native follow-ups require the existing Unreal owner/Boss integration lane; client follow-ups require a coordinator claim. No new ownership or execution permission follows from this table.

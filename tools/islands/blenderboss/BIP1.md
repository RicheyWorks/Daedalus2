# BIP 1: Blender import packets (blender-team)

Turns one huge island glb into small, bounded, hashed packets plus a placement manifest, so Unreal ingests the island in bounded steps instead of one 14.5 MB mesh (the Oct 13 05:54 GPU page-fault crash). Blender-side only: nothing here imports into Unreal.

- `bip_split.py <island.glb> <packet dir> <manifest.json>`: deterministic (no clocks or randomness; the same input gives byte-identical packets). Terrain and underside are baked to island space and cut into a quadtree of chunks by triangle centroid on XZ (no triangle is cut, so edges stay watertight). Each distinct prop mesh is written once into a library packet. Every source node becomes a placement row (translation, rotation, scale, world AABB). Hard caps per packet: 12,000 tris, 1.5 MiB, 64 materials; the splitter refuses to write a packet over any of them.
- `bip_verify.py <manifest> <packet dir> [source.glb] [--rebuild]`: recomputes sizes, sha256, triangle counts and bounds from the packet files, checks index ranges, finiteness, caps and placement references, then the totals against the source, and with `--rebuild` that a second split is byte-identical. Exit 0 only if every check passes.
- `bip_render_check.py` (`blender -b --python ... -- <manifest> <packet dir> <source.glb> <out dir>`): renders the source and the reassembled packets from one top-down camera and prints the pixel difference.
- Prop_Island_Flagship_BlenderBoss.glb (15,191,232 bytes, 1,732 nodes, 448,046 triangles by instance): 28 terrain packets + 39 prop packets (1,164 distinct meshes, 1,730 placements); largest packet 9,592 tris / 920,952 bytes; verify 7,461/7,461 checks; reassembled top-down render differs from the source in 0.0% of pixels.
- Packets live in bot-team `art/packets/flagship/` (outside the watched `art/glb`); the manifest is `data/islands/blenderboss/flagship.bip.json`. Ingest one packet at a time inside a claimed turn, never from the art watcher: terrain first, then the prop library, then placements.
